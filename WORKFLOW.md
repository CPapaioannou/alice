# ALICE — Dataset & Training Workflow

Operational runbook for the Frigate→YOLO fine-tuning loop, written against the
post-B1..B4 `dev` branch (deterministic export splits, capture-time sorting,
hardened API, thread-safe viewer + warm hash precompute).

Two loops: **fresh start** (one-time) and the repeatable **top-up loop**
(recurring). The core model is a *single growing dataset* with periodic
re-fine-tuning.

---

## Phase 0 — Fresh start setup (one-time)

1. **Deploy the build.** `alice.py` is regenerated by `python3 builder.py`
   (git-ignored artifact). Restart the Alice container.
2. **Delete the contaminated dataset** (only if starting fresh). Anything
   built before the B1 split-integrity fix has train/val duplication. Delete
   the dataset directory rather than trying to settle it:
   ```
   rm -rf datasets/default
   ```
3. **Create the new dataset.** UI → Datasets → create e.g. `frigate-v1`.
   This becomes your one growing dataset for all future top-ups.
4. **Confirm settings** (`alice.conf` / Settings tab):
   - `FRIGATE_DB` + `FRIGATE_DB_SSH_HOST` reachable (source of snapshots)
   - `TEACHER_MODEL` = your teacher (e.g. `yolo11x.pt`)
   - `STUDENT_MODEL` = base student (e.g. `yolo11s.pt`)
   - `DEVICE` = `nvidia` (GPU) or `auto`

## Phase 1 — Initial data run

5. **Export.** Trainer → Export, full (no limit). Note: the Frigate query
   (`SELECT id, camera FROM event WHERE has_snapshot=1`) pulls **all classes,
   all time** — there is currently *no* class filter at export. If you only
   want specific classes, filter them out later in the viewer (delete the
   unwanted images) or treat the rest as a known limitation.
6. **Dedup.** Trainer → Dedup (pHash on). On a fresh export this just settles
   duplicate frames into the deterministic split — cheap.
7. **Annotate.** Trainer → Annotate with the teacher model (auto-labels).
8. **Review (human, do not skip).** Viewer is now chronological. Spot-check the
   teacher's boxes, fix/delete bad ones. This is the quality ceiling for the
   student model.
9. **Train.** Trainer → Train (student model, your epoch/LR settings).
10. **Export ONNX.** Trainer → ONNX Export.
11. **Deploy to Frigate.** Swap the new ONNX in, restart Frigate, verify
    detections on the live feed.

> Shortcut: steps 5–10 are also the **Trainer → Pipeline** (runs
> export→dedup→annotate→train→ONNX as one background job). Usable, but break
> before step 8 to review, or run the pipeline through Annotate, review, then
> kick off Train+ONNX.

## Phase 2 — Top-up loop (recurring)

12. **Export again on the *same* dataset.** Key B1 property: idempotent —
    existing events keep their split and files, only *new* Frigate events are
    added. A no-op second run confirms nothing re-rolled.
13. **Dedup → Annotate.** Teacher labels only the new images; existing labels
    are untouched by design.
14. **Review** the new annotations.
15. **Retrain — warm start.** Point the train step at the **previous round's
    `-finetuned.pt`** (it lands in `MODELS_DIR` after each train) instead of
    base, with a lower learning rate (≈1–2× your initial LR). This
    fine-tunes from where the model left off.
    - Alternative (if you see drift/forgetting): train from base again on the
      full accumulated dataset — that's what the single growing dataset buys
      you; it gets stronger each round.
16. **ONNX → deploy → verify.**

## Hygiene

- **Val split stays honest.** Split assignment is per-event and sticky, so the
  ~10% val set grows with train. Don't hand-delete files — it breaks the
  determinism.
- **Dataset size.** Frigate grows it unboundedly. When it gets heavy, lean on
  Dedup (raise pHash similarity a bit) rather than deleting.
- **After each top-up**, glance at the trainer report + viewer train/val
  counts before deploying.

## Full factory reset — what to wipe

ALICE's own state lives in three places (all under the repo, all git-ignored
or regenerable):

| Path | What it is | Wipe? |
|---|---|---|
| `datasets/<name>/` | All datasets (images + labels) | **Yes** |
| `datasets/output/` | Training runs (finetune weights, results.csv, plots) | **Yes** |
| `models/*-finetuned.*` | Your fine-tuned `.pt`/`.onnx` artifacts | **Yes** (if you want them gone) |
| `models/yolo*.pt` (base) | Downloaded pretrained weights (teacher/student/base) | **No** — keep; re-downloading is wasteful |
| `alice.conf` | Your config (paths, models, settings) | **No** — it just points at the dirs, which are recreated |

One-liner for a complete reset of *datasets + training + labelling* while
keeping base models, config, **and** the `datasets/` root (which the UI's
dataset-creator requires to exist):

```
rm -rf datasets/* models/*-finetuned.*
```

**Do NOT wipe** (out of ALICE's scope, they're *inputs*):
- The Frigate DB (`FRIGATE_DB`, e.g. `/home/frigate/config/frigate.db`) —
  your event source. Wiping it loses Frigate history, not just ALICE state.
- `LIVE_DIR` / `EXPORTS_DIR` (e.g. `/home/chris/frigate-remote/clips`,
  `.../exports`) — Frigate's live snapshots / video exports, re-scannable.

After wiping, recreate the dataset dir (UI → Datasets → create) and start the
Phase 1 loop.
